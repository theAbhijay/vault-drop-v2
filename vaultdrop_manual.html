1. Executive Vision & Foundational Philosophy

VaultDrop is born from an uncompromising conviction: public workstations, laboratory PCs, and shared terminal screens are fundamentally hostile computing environments.

The Brand Identity & Phonetics Rule

The system name is strictly styled and pronounced as VaultDrop (capital V, capital D). It must never be written as lowercase Vaultdrop or generic text. It represents the immediate, safe dropping of sensitive digital assets into an impenetrable, self-destructing vault.

The Fundamental Problem

When students, engineers, and researchers need to transfer files between their personal mobile phones and shared public computers (university labs, library kiosks, printing shops, or client conference rooms), they are forced into dangerous habits:

  • Typing their personal passwords into shared keyboards equipped with potential hardware or software keyloggers.
  • Leaving persistent browser cookies and active sessions stored in shared browser profiles.
  • Leaving files in public "Downloads" folders where subsequent users can inspect, copy, or recover them.
  • Plugging in USB thumb drives that can be infected with autorun firmware malware.

The VaultDrop Doctrine: Zero Keystrokes, Zero Trace

VaultDrop completely eliminates keystrokes on untrusted machines. Through cryptographic cross-device handoffs, dynamic SVG chromatic QR codes, and automated 24-hour file cremation, a user can stage, preview, download, and zip files without leaving a single trace of their identity or data.

🔒 Zero-Keystroke PC Login
Workstation screens display a rotating, 2-minute ephemeral cryptographic token in chromatic vector format. Smartphones scan and authorize in 250 milliseconds.
🔥 24-Hour File Cremation
Every uploaded file carries an explicit UTC expiration timestamp. Unclaimed or completed payloads are permanently purged via database triggers.
⚡ Instant 0ms Panic Wipe
Single-click or hotkey screen sanitizer that flushes auth storage, revokes signed URLs, and clears the DOM in 0 milliseconds.
🛡️ BFCache Navigation Guard
Prevents browser "Back" button attacks by detecting cached DOM reconstruction and enforcing immediate re-authentication.
Abhijay Chauhan's Architectural Mandate: "Software should feel alive. It should not look like another cold, lifeless utility. Every color, every transition, and every loading frame must communicate precision, beauty, and security."

3. The Custom Peacock Loader & Temporal Psychology

In modern high-speed web apps, instantaneous state transitions can create cognitive disorientation. VaultDrop solves this with the Peacock Loader and a strictly calibrated 2-second perceptual delay guarantee.

The 2000ms Perceptual Minimum Guarantee

When a user submits credentials or creates a new vault, if the system authenticates in 30ms, the screen appears to jerk or flicker, leaving the user unsure whether cryptographic keys were truly initialized.

VaultDrop enforces an intentional minDelay = Promise.all([auth, sleep(2000)]). This guarantees that the user observes the cryptographic handoff animation. The interface feels intentional, heavy, and secure.

Peacock Kinetic Mechanics & Immediate Dashboard Mounting

The Peacock loader is engineered using pure SVG vectors and dual accelerated CSS orbital keyframes:

  • Dual Accelerated Orbits: Outer and inner concentric rings rotate at 1.8s and 2.4s intervals in counter-rotation, creating a gyroscopic depth effect.
  • Vertical Bouncing Spheres: Three central chromatic spheres bounce with sinusoidal easing curves, running at an accelerated 0.4s period with 0.1s staggered delays.
  • Zero Secondary Blockers: Once the 2-second Peacock authentication period completes, the user lands directly into the fully rendered vault dashboard. All secondary "Initializing..." full-screen freezes have been eliminated; storage syncs silently inline.

@keyframes peacockOrbital {
  0% { transform: rotate(0deg) scale(0.96); opacity: 0.7; }
  50% { transform: rotate(180deg) scale(1.04); opacity: 1; }

5. Bidirectional QR Pairing & The 3-Tier Fallback

VaultDrop features a zero-configuration bidirectional hardware bridge allowing either device to authenticate the other without typing credentials.

Scene 1: PC Logged In First (Handoff to Phone)

When a user logs in on a computer first and wants to access their vault on their phone:

  1. The PC dashboard displays an "Open on Smartphone" modal featuring a dynamic chromatic QR code.
  2. On the smartphone, the user opens Google Lens or their native camera and points it at the screen.
  3. The phone opens the URL /pair?handoff=username&uid=id and is authenticated instantly with zero keyboard inputs.
Scene 2: Phone Logged In First (Handoff to PC)

When a user is on their mobile phone and wants to unlock an untrusted lab PC:

  1. The untrusted PC opens /login on the QR tab. It displays a real-time cryptographic pairing token.
  2. The user points their smartphone camera at the PC screen.
  3. The phone opens /pair?token=... and prompts: "Authorize Workstation Session?"
  4. Tapping Approve completes the handshake via Supabase real-time triggers. The lab PC unlocks within 400ms!

The 3-Tier Universal Fallback Matrix

What if someone does not have Google Lens installed, or has camera permissions disabled? VaultDrop provides a fail-safe, 3-tier cascade:

Tier Fallback Mechanism Implementation Detail
Tier 1 (Primary) Native Google Lens App Direct Intent Direct Android intent launch: intent://#Intent;package=com.google.ar.lens;end;. Completely eliminates search website redirects.
Tier 2 (Universal) Built-in iOS / Android Camera Every modern iOS (11+) and Android (9+) camera app auto-detects QR codes natively with zero additional software.
Tier 3 (No Camera) 6-Character Workstation PIN PC screen displays a high-visibility PIN (e.g. B9C3F1). User types 6 characters on mobile to resolve the token via findTokenByPin().

6. Live Upload Tracking & Storage Quota

Transferring files into an encrypted ephemeral vault requires clear visual confirmation. Users must never wonder whether their file is stalled or actively encrypting.

Live Chromatic Progress Engine

VaultDrop integrates an active progress tracking pipeline in file-helpers.ts and DropZone.tsx:

  • Client Sanity Validation (0% - 15%): Verifies file size, filename constraints (1–255 characters), and checks cumulative quota before network transmission.
  • Binary Storage Staging (15% - 70%): Streams file bytes directly to the encrypted Supabase Storage bucket with live percentage feedback.
  • Database Metadata Registration (70% - 90%): Executes PostgreSQL row insert with strict foreign key constraints and triggers.
  • Signed URL Generation (90% - 100%): Generates short-lived, tamper-proof 60-second download tokens.
Visual Progress Architecture in DropZone

During upload, the standard drop zone collapses smoothly into an Apple chromatic progress track:

quarterly_financial_report.pdf 72%

Post-upload, a 2.2-second emerald confirmation banner confirms multi-device synchronization before resetting.

Direct Blob-Based Download Engine (PC & Mobile Universal)

Standard browser downloads often fail silently on cross-origin cloud storage signed URLs (Chrome and Safari ignore the download attribute on cross-origin links). VaultDrop implements a bulletproof Same-Origin Blob Download Pipeline:

  • Direct Bucket Binary Stream: Downloads binary payload directly via Supabase Storage client or signed URL fetch into an in-memory Blob.
  • Same-Origin ObjectURL Link Injection: Dynamically creates a temporary blob: URI, injects an invisible anchor tag with the exact sanitized filename, triggers a programmatic click, and revokes the URL memory after 2 seconds.
  • 100% Platform Reliability: Guaranteed to trigger native file downloads on Windows, macOS, Linux, iOS Safari, Android Chrome, and Brave.

Strict Quota & PostgreSQL Trigger Defense

To prevent server denial-of-service, VaultDrop enforces hard architectural boundaries:

  • Max Single File Size: 20 MB strictly enforced on client and bucket policy.
  • Max Vault Account Cap: 50 MB total cumulative payload per user.
  • Atomic Trigger Rollback: If a race condition bypasses client checks, PostgreSQL trigger enforce_storage_quota_trigger raises an exception and automatically purges the orphaned storage object.

8. Ephemeral Zero-Trace Security & Defense-in-Depth

Security in VaultDrop is not an afterthought or an optional toggle; it is the fundamental fabric of the application lifecycle.

1. 24-Hour File Auto-Destruction

Every file uploaded to VaultDrop is stamped with an immutable UTC expiry date 24 hours into the future. A background PostgreSQL scheduled worker evaluates: 

DELETE FROM files WHERE expires_at < NOW();

The corresponding storage bucket artifacts are purged automatically via bucket lifecycle policies, ensuring that forgotten files do not persist indefinitely.

2. 30-Minute Inactivity Session TTL

If a user walks away from a public library workstation, VaultDrop will not remain open. An idle activity tracker monitors keyboard, mouse, and touch events:

  • At 28 minutes of inactivity, a pulsing warning banner appears with a direct button to extend the session.
  • At 30 minutes, the session is terminated, storage keys are purged, and the browser is redirected to /login?reason=timeout.

3. Instant 0ms Panic Wipe with 10-Second Auto-Dismiss

In emergency situations (e.g. someone approaching the user's terminal), clicking the high-visibility red Panic button triggers an immediate emergency shutdown:

  • Session tokens, user profiles, and decryption keys are purged synchronously from memory and storage in 0 milliseconds.
  • The page redirects to /login?reason=panic, displaying a high-contrast emergency warning banner.
  • The panic notice automatically self-dismisses after exactly 10 seconds, leaving a clean, neutral login screen without leaving clues about previous activity.

4. BFCache (Back-Forward Cache) Defense

A notorious security vulnerability in modern browsers is the Back-Forward Cache: when a user clicks "Log Out" and walks away, an intruder can click the browser's "Back" arrow to view cached pages.

VaultDrop neutralizes this via the pageshow event listener. If e.persisted is detected, the authentication guard checks the active session and instantly redirects to the login screen, denying cached DOM rendering.
